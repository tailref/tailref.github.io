TailRef Studio 1.4.4 is out — now on macOS

24 November 2026 Emre Melik Nameli 5 min read

TailRef Studio now runs on macOS. It is the same workspace as on Windows and Linux — collect references, draw over them and pose 3D models in one window — and 1.4.4 is the first release with macOS builds next to the others. The rest of the release is a long pass over the settings panel, which had more broken switches than I expected.

Two macOS builds

One image for Apple silicon (M1 and later), one for Intel Macs. Both are built from the same source, and the native inkcore module is compiled separately for each architecture, so the 3D view runs natively on both instead of falling back to the JavaScript renderer.

  • Apple silicon — macOS-TailRef-1.4.4-arm64.dmg
  • Intel — macOS-TailRef-1.4.4-x64.dmg

On itch.io each build is delivered as a zip archive that holds the disk image: unpack it, open the image and drag TailRef Studio into Applications.

.tail boards open from Finder

TailRef registers itself as the app for .tail boards, so double-clicking one in Finder behaves like it does on Windows and Linux: a running window takes the file and switches to it, or a cold start loads the board directly. No drag-and-drop, no "open with" detour.

Signing and first launch

The builds are ad-hoc signed, not notarized: there is no Apple Developer ID behind them yet, so Gatekeeper asks for confirmation the first time. Right-click the app and choose Open, or run:

xattr -dr com.apple.quarantine "/Applications/TailRef Studio.app"

After that it starts normally. macOS has no in-app updater, so update by downloading the new image — the same rule as Linux.

A package that does not start cannot be released

The macOS job no longer stops at "electron-builder finished". It copies the .app out of the disk image, starts it in a temporary data folder on an isolated port, and checks that the app becomes ready and that the board scene loads. If the packaged app does not start, the release is not created. That check runs for both architectures.

Download names

GitHub has no folders inside a release, so asset names now start with the platform — Windows-, Linux-, macOS- — and the download list groups itself. latest.yml keeps its required name and points at the renamed installer, so Windows in-app updates keep working.

Settings and interface audit

Several controls in the settings panel were decorative: they saved a value and nothing read it. Others broke in ways that were easy to miss. All of these are fixed:

  • High contrast never applied. Its selector had the same specificity as the theme selector, so the colors were silently overridden.
  • Rain and snow vanished from custom themes. A theme saved from Rain or Snow lost both the effect and the backdrop gradient. Themes now store the effect and the backdrop, and the canvas follows the active ambient setting.
  • A gallery pick reverted on a mode switch. The choice is now written to the key of the mode you are in, so Reference and Drawing can keep different themes.
  • "Cursor-anchored zoom" did nothing. It now zooms around the pointer. It is on by default, which preserves the old behavior.
  • "Editor grid step" did nothing. It now drives the grid overlay; the default is 32 px.
  • The settings footer was clipped. The e-mail and copyright lines moved to a grid: copyright under the e-mail, buttons spanning both lines.
  • Narrowing the panel collapsed the text to one letter per line. The panel is a container query now: below 560 px the navigation turns into a horizontal strip, the footer takes the full width and Save/Reset get their own row.
  • The update panel described the wrong platform. With the updater disabled it said "On Linux…" everywhere; macOS now has its own sentence, translated into every language.
  • Drawing-mode top bar stretched with the window. Buttons are pinned to 30 px, the bar keeps its height, and the collapse/expand animation is back.
  • Smaller things: the empty-board hint no longer shows the logo and wordmark, and the mode order is identical in every panel (3D Pose → Reference → Drawing).

Ten languages, no gaps

The last 275 translation keys were closed in eight languages. TailRef now ships ten languages and 15,087 keys, and no key falls back to English — the completeness check in CI fails the build if one does.

Windows and Linux

Behaviour is unchanged. The Windows installer still updates itself from GitHub Releases and the portable build still points at the download page. Linux ships the AppImage plus deb and rpm packages on GitHub.

Download

Windows installer and portable, Linux AppImage, deb and rpm, macOS arm64 and Intel images — seven downloads on GitHub, all version 1.4.4, with SHA256 checksums. On itch.io the same builds are listed as five downloads. Windows 10/11 x64, Linux x86_64, macOS on Apple silicon and Intel. Free and open source, GPL-3.0-or-later.
